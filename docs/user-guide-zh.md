# CaseFile AI v1.0 中文用户手册

适用读者：第一次使用本工具的 Windows 用户，以及律师、法务、法学生和研究人员。本文按当前界面编写，不要求理解编程或数据库。

**版本说明**：当前程序版本为 **1.0.0**。本公开候选仅提供源码，尚无可下载的 Windows ZIP；下文安装包操作说明记录已验证的本地流程，`CaseFileAI-1.0.0-windows.zip` 并未作为公开附件发布。工具定位为单机、本地优先、证据可追溯；发布能力与限制见 [发布说明](../RELEASE_NOTES.md)。安装细节见 [Windows 安装说明](windows-installation.md)，备份细节见 [数据管理说明](data-management.md)。

第一次使用的顺序：**Setup → Prepare Models → Start → 创建案件 → 导入 PDF → 建立索引 → 检索 → 按需配置 AI → 提问并核对引用 → 抽取事实与分析 → 备份 → Stop**。

## 1. CaseFile AI 是什么

CaseFile AI 是**本地优先、证据可追溯的 AI 卷宗分析工具**，帮助你整理材料、查找证据、查看带来源的回答与分析。

原始 PDF、识别出的文字、数据库（SQLite）、检索索引和已保存结果保存在本机。PDF 解析、扫描文字识别（OCR）、关键词检索（BM25）和本地向量检索模型（BGE）在本机运行。部分 AI 分析会调用你配置的模型服务，向其发送必要内容；详见 [隐私章节](#guide29)。首次安装和模型准备通常需要联网，因此不能把本工具理解为“完全离线”或“所有内容永不离开电脑”。

## 2. 它能做什么
<a id="guide02"></a>

- 创建、选择、重命名和归档案件。
- 导入原生或扫描 PDF，保存原文件及历史版本。
- 用关键词或语义含义查找材料，查看原文片段和页码。
- 使用明确启用的模型服务，基于检索证据提问并核对引用。
- 从已验证回答中抽取最小事实陈述（Claim），检查回答事实的覆盖情况（Coverage）。
- 比较相关事实，查看日期、金额、行为和人物四类矛盾结果，以及时间线（Timeline）。
- 导出单个案件的已有分析为 JSON / Markdown；创建全部案件的完整备份并恢复为新副本。

未配置云模型时，案件管理、导入、本地 OCR、索引、搜索、原文查看、备份、恢复和已有结果导出仍可使用；本地 OCR / 检索需要先准备相应模型。

<a id="guide03"></a>

## 3. 它不能保证什么

本工具不能保证完整理解全部案件、找出所有事实或所有矛盾，也不能保证 OCR 或 AI 回答百分之百正确。“没有检测到”不意味着事实不存在。

CaseFile AI 是辅助分析工具。最终事实核对和专业判断仍需要你基于原始材料完成；输出不是法律意见、自动裁判或已经确定的事实。金额、日期、编号、姓名尤其需要逐项核对。

## 4. 第一次安装

1. 若未来取得经许可审查的 Windows 交付 ZIP，在资源管理器中完整解压到可写、长期保留的程序目录，例如 `C:\Tools\案件分析 CaseFile AI\`。不要直接在 ZIP 窗口里运行入口。
2. 双击 **Setup CaseFile AI.cmd**。它准备固定 Python 3.12.13、按锁文件安装依赖并进行应用自检；用户不需要手动输入安装命令。
3. 等待结果。Setup 可重复运行；已有配置和案件不会被自动清空。再次 Setup 前先 Stop。
4. 双击 **Prepare Models CaseFile AI.cmd**，按下一章等待本地模型准备完成。
5. 双击 **Start CaseFile AI.cmd**。

Setup 不要求 API key，也不自动开启云模型。Setup / Prepare 的控制台会保留结果，按任意键关闭。桌面 Start / Stop 快捷方式会尝试创建；失败时直接使用程序目录的 CMD 即可。

如果提示 uv 缺失或版本不符，按以下步骤处理：

1. 打开 [官方 uv 0.11.21 发布页](https://github.com/astral-sh/uv/releases/tag/0.11.21)。
2. 下载 Windows x64 文件 `uv-x86_64-pc-windows-msvc.zip`，解压取得 `uv.exe`。
3. 在 CaseFile AI 程序目录创建 `.tools` 文件夹，把它放成 `.tools\uv.exe`，再双击 Setup。

Setup 不会自动下载 uv，不执行远程安装脚本，也不要求永久修改系统脚本执行策略。当前交付面向 Windows x64；若单位禁止脚本运行，请按单位政策处理。原生运行库问题见 [Windows 安装说明](windows-installation.md)。首次安装需预留网络、下载与磁盘时间，没有固定耗时保证。

<a id="guide05"></a>

## 5. 准备本地模型

双击 **Prepare Models CaseFile AI.cmd**。你会看到“正在准备本地向量模型”“正在检查 OCR 模型”。程序实际加载模型并用合成输入检查，不分析你的案件，也不要求云模型配置。

首次运行可能下载模型，等待时间取决于网络、缓存和电脑性能。失败可检查网络、空间和目录权限后重新运行；不会破坏既有案件。首次导入扫描件或建立索引也可能触发未准备模型的下载，因此建议提前完成 Prepare。

向量模型沿用 Hugging Face 的缓存，默认 `%USERPROFILE%\.cache\huggingface\hub`；OCR 模型通常位于程序环境 `.runtime\Lib\site-packages\rapidocr\models`。它们不是案件数据，也不会进入备份。自定义缓存方法见 [安装说明](windows-installation.md)，不要为更新程序手工复制几 GB 模型。

Start 和“刷新系统状态”不会主动下载模型。“可用”通常表示必要文件存在；“尚未加载”只表示当前服务尚未使用它，不一定是故障。

<a id="guide06"></a>

## 6. 启动软件

双击 **Start CaseFile AI.cmd** 或桌面 Start 快捷方式。程序完成轻量检查，启动本地服务，等待就绪后自动打开默认浏览器，默认地址是 `http://127.0.0.1:8000/`。

第二次、第三次双击会复用已验证的现有实例并打开页面，不再启动第二个服务。如果浏览器未打开但入口显示服务已就绪，可手动访问它显示的地址；如果提示启动失败，先处理原因，不要只反复刷新网页。

端口被别的程序占用时会提示“端口 8000 已被其他程序占用”，不会悄悄切到其他端口。核实占用程序后正常关闭它，或请维护人员协助；不要按名称强杀所有 Python。较老版本或开发入口的服务应先在原入口正常停止。

<a id="guide07"></a>

## 7. 停止软件

双击 **Stop CaseFile AI.cmd** 或桌面 Stop 快捷方式，等待停止结果。入口只管理验证匹配的 CaseFile AI 实例，不会按 Python 名称结束其他程序，也不会默认强制杀进程。

**关闭浏览器 ≠ 停止服务。** 长操作可能需要等待；停止超时后可稍后重试。不要在导入、索引、备份或恢复进行时通过强杀进程代替 Stop。开发方式启动的服务需回到原终端正常停止。

<a id="guide08"></a>

## 8. 创建和选择案件

1. 在左侧 **新案件名称** 输入名称，点击 **创建案件**。
2. 在左侧 **当前案件** 下拉框选择要处理的案件。
3. 先核对当前案件名称，再导入材料或分析，避免选错案件。

名称去除首尾空格后不能为空，最长 200 字符。名称相同不代表同一个案件；重命名不改变内部身份或已有引用。第一次练习请使用合成或已人工脱敏的 PDF。

<a id="guide09"></a>

## 9. 导入 PDF

1. 选择案件，进入 **材料与索引**。
2. 在 **选择 PDF 材料** 选择文件，点击 **导入 PDF**。
3. 等待“导入 PDF 并解析 / OCR”完成，核对材料名、页数和当前版本。
4. **再点击“建立索引”**，索引可用后才能进行完整检索和提问。

**导入和建立索引是两个步骤。** 导入负责保存 PDF、解析文字、必要时 OCR 并保存材料版本；导入成功不代表索引已建立。当前页面一次选择一个 PDF，可逐份导入。

当前只支持未加密 PDF，每份不超过 **50 MiB**，页数为 **1–500 页**，文件名最长 255 字符。Word、图片等需先在其他软件中转成 PDF。同一案件中重复上传内容相同的 PDF，可能复用已有材料 / 版本，不会因为换名就生成新内容；页面目前不一定单独提示“重复 PDF”。需要更新同一份材料时使用 [添加新版本](#guide18)。

<a id="guide10"></a>

## 10. OCR 什么时候执行

导入时逐页判断：有足够可读取文字的 PDF 页面优先读取原生文字；原生文字不足的页面会尝试本地扫描文字识别（OCR）。混合 PDF 可以同时包含这两类页面，不需要单独按 OCR 按钮。

识别结果并非百分之百正确，`O / 0`、`I / l / 1`、`S / 5`、`B / 8` 等可能混淆。金额、日期、编号、姓名应对照原始 PDF，不能把识别文字当成已核实事实。程序无法保证安全自动纠正这些字符。

**更新索引不会重新 OCR。** 索引使用已保存的解析文字；若识别有误，先核对原文并改善源 PDF，再按材料版本方式重新导入。当前 GUI 没有直接编辑 OCR 文字或强制重新 OCR 的功能；不要手工改数据库。

<a id="guide11"></a>

## 11. 建立和更新索引

在 **材料与索引** 点击 **建立索引** 或 **更新索引**，等待操作完成。索引让软件能够从已有文字中查找证据，不重新识别扫描页。

| 界面实际状态 | 含义 | 怎么做 |
| --- | --- | --- |
| 尚未建立索引 | 材料已导入，尚不能完整检索 | 点击建立索引 |
| 索引可用 | 当前材料版本的检索准备完成，即“已就绪” | 可以检索或提问 |
| 索引需要更新 | 材料新增版本、索引不完整或程序索引版本变动 | 点击更新索引 |
| 正在建立索引 | 正在处理，相关操作可能暂不可点击 | 等待完成，避免重复提交 |
| 上次索引失败 | 最近处理未成功，已导入材料仍保留 | 检查系统状态、模型和空间，再重试 |

看到“索引版本已更新”或类似过期提示时，重新建立 / 更新索引，不必为了索引变化重复导入或 OCR。案件中只要还有未完成的当前材料，整体可能尚未就绪。新增材料或新版本后应再次检查。

<a id="guide12"></a>

## 12. 搜索材料

1. 确认案件及索引可用，在 **材料与索引** 找到 **检索案件材料**。
2. 输入姓名、金额、日期、合同关键词或具体行为描述，点击 **检索**。
3. 阅读文件名、页码和命中片段，点击 **打开此版本原文** 核对。

检索在本机完成，不需要云模型或 API key；当前 GUI 综合关键词与语义查找，没有单独的检索模式切换按钮。极短或模糊的“日期”“金额”可能无法唯一命中，宜改成“甲公司合同签署日期”或“第二笔转账金额”。姓名、事件和文件名同时给出通常更容易限定范围。

未找到结果不等于材料没有记载：检查案件、索引、OCR 和用词，再换更明确的查询。搜索原文后再决定是否需要 AI 提问。

<a id="guide13"></a>

## 13. AI 提问与安全拒答

1. 先完成导入与索引，并按 [模型配置](#guide25) 明确启用服务。
2. 进入 **提问与引用**，在 **询问材料中的事实** 输入具体问题，点击 **提问**。
3. 等待“生成并验证回答”，查看回答状态，再逐项核对引用。

问题最长 1,000 字符。可以问“《合成转账凭证》第 1 页记载的转账金额是多少？”；避免要求软件直接裁定胜诉、责任或代替法律判断。文件、页码等写在问题里是自然语言限定，不是独立筛选控件，也不保证一定命中。

提问及支持 / 对齐验证可能向配置的服务发送问题、检索出的证据原文、文件名、页码、版本标识及相关事实。一次提问可能包含多次模型请求，存在等待和服务计费；请求超时不是整个分析流程的总时限。重复相同问题可能直接返回已保存结果，不保证每次重新请求模型。系统不会自动脱敏。

| 回答状态 | 如何理解 |
| --- | --- |
| 已验证 | 通过当前引用和事实验证流程，仍需人工核对原文 |
| 证据不足 | 未形成有充分引用支持的答案；这是正常的安全反馈 |
| 索引未完成 | 先到材料页面建立 / 更新索引，再重新提问 |
| 答案验证未通过 | 本次回答不能作为有效答案使用；核对问题和原文 |

“证据不足”不是软件坏了，也不证明事实不存在。当前已索引证据、检索结果或验证过程不足以形成可靠回答；保守验证也可能拒绝本来可以回答的问题。先确认材料已导入、索引可用，补充材料、缩小问题或指定来源页码。不要反复问到模型“答出来”，更不要要求它忽略证据。

AI 未配置 / 未启用时，本地功能仍可使用；开启前请阅读 [隐私章节](#guide29)。

<a id="guide14"></a>

## 14. 查看引用（Citation）和原文

回答中的引用用于把事实追溯到材料：文件名说明来源文件，版本说明当时所用材料，页码是该 PDF 内从第 1 页起的页面序号，原文片段是解析 / OCR 得到的证据文字。PDF 内印刷页码可能与页面序号不同。

1. 读回答下每条事实及其引用片段。
2. 点击 **文件名 · 第 N 页**，打开所引用版本的 PDF；浏览器支持时定位到该页，不支持时手动翻页。
3. 对照原件核实文字、上下文、日期和金额。字符级高亮不是保证提供的功能。

**引用合法 ≠ 法律结论正确。** 通过引用验证只说明符合当前来源和验证规则，不能免除原文与专业判断核对。补充引用也可能需要人工确认是否真正支持所述事实。

GUI 引用卡片显示文件名、真实版本、页码与原文，例如 `v2（当前版本）` 或 `v1（非当前版本）`；点击链接指向记录的来源版本。可以对照 **历史版本 / 添加新版本 → 查看历史版本**，或导出分析报告。版本信息无法取得时会明确提示，不推测版本号。Markdown 明确写出 `来源：v1（非当前版本）`，JSON 包含对应版本信息。这意味着回答使用历史 v1，而当前材料已有更新版本，不能把旧证据误当新版本内容。

## 15. 查看事实（Claim）与覆盖检查（Coverage）

Claim 是系统从已验证回答中提取出的最小事实陈述。例如“甲公司于某日签署合同”和“合同金额为某数”是两条事实，仍各自需要引用支持。

1. 在 **提问与引用** 获得带有效引用的回答。
2. 进入 **事实与覆盖检查**，找到该问题，点击 **抽取事实**；此步骤及其支持检查可能调用模型服务。
3. 阅读 **已抽取事实** 及原文。
4. 点击 **查看覆盖检查**，检查“完整覆盖：是 / 否”、未覆盖片段，以及引用证据是否有效。

Coverage 是本地检查：看当前已验证回答的事实是否有对应 Claim，以及其来源链是否有效。**Coverage 不代表完整案件覆盖**，不检查尚未提问的材料是否全部理解。“完整覆盖：是”也不是事实全部正确的保证。未覆盖时先比较回答、事实和原文，再决定是否补充提问或材料。

改变模型配置或程序版本可能改变当前页面展示的分析范围；历史结果并不因此被删除，可用分析导出保留和查看不同历史范围。

<a id="guide16"></a>

## 16. 查看矛盾分析

1. 先获得有效回答并抽取事实，进入 **候选与矛盾**。
2. 阅读 **候选事实对** 的两侧事实，核实是否同一事件、同一人物角色或同一金额字段。
3. 点击 **运行四类矛盾检测**，查看日期、金额、行为、人物的结果、原因和两侧来源。

| 界面结果 | 含义 |
| --- | --- |
| 存在矛盾 | 当前流程判定这对事实不兼容，应人工核对上下文 |
| 未判定为矛盾 | 本次比较没有形成矛盾判断，不代表整个案件不存在矛盾 |
| 待确认（uncertain） | 证据、事件范围、主体或语义无法可靠判断 |
| 本次临时反馈 | 语义服务失败或输出无效；未持久化，重新加载后可能消失 |

日期 / 金额比较的规则部分在本地运行；行为 / 人物语义判断可能调用配置的模型。若本次候选包含需要模型的类型，未启用 AI 时整个检测操作可能被阻止，并非承诺先输出其他类型。

候选生成可能漏掉应比较的事实，也可能把不同事件放在一起。**当前没有检测到矛盾 ≠ 案件不存在矛盾**；“待确认”不能当成确定矛盾。请检查双方原文和候选范围，不只看颜色或数量。

<a id="guide17"></a>

## 17. 查看时间线（Timeline）

进入 **时间线**，查看事实、日期和引用。它从已有、来源有效的事实在本地整理，不会替你补全未记载日期。

日期可能只有年、年月，或完整年月日：只有年 / 月会显示 **部分日期**，完整日期显示 **日期明确**。没有可识别日期的事实也可能作为 **日期未知 / 未知日期** 列出，不会被强行赋予日期。时间线不是完整事实清单，也不自动合并重复事件；仍应打开原文核对。

<a id="guide18"></a>

## 18. 查看和添加文档版本

1. 在 **材料与索引** 找到已有材料，展开 **历史版本 / 添加新版本**。
2. 点击 **查看历史版本**，查看 v1、v2 等编号及标记为“当前”的版本；点击 **打开此版本原文** 查看指定 PDF。
3. 在 **选择新版本 PDF** 选择修订文件，点击 **添加新版本**。
4. 新版本保存成功后检查并 **更新索引**。

旧版本不会被替换或删除；历史回答 / 引用仍指向当时版本，这是证据追溯所必需的。版本更新也不会自动重新生成历史回答。文件内容相同可能仍复用已有版本；当前界面没有材料创建时间展示，也没有切换“当前版本”回旧版的按钮。

<a id="guide19"></a>

## 19. 案件重命名

选择案件，展开左侧 **当前案件管理**，在 **案件显示名称** 输入新名称，点击 **保存名称**。去除首尾空格后不能为空，最长 200 字符。重命名只改显示名称，案件身份、材料版本及引用不变；核对左侧名称和当前标题已更新。

<a id="guide20"></a>

## 20. 案件归档和恢复归档

在 **当前案件管理** 点击 **归档案件**。归档只隐藏日常列表，**不是删除**，材料与分析仍保留。

查看时勾选左侧 **显示已归档案件**，选择带“已归档”标记的案件。需要恢复到日常列表时点击 **恢复归档**。归档案件仍允许继续处理、分析和导出，不是锁定只读。当前版本不支持 GUI 永久删除案件或文档。

<a id="guide21"></a>

## 21. 导出分析

1. 选择案件，点击 **导出案件分析 JSON** 或 **导出案件分析 Markdown**。
2. 等待完成，点击 **下载分析报告**，保存到自己选定的安全位置。
3. 打开报告，核对案件、生成时间、来源版本和分析范围。

JSON 适合结构化保存或后续处理；Markdown 适合人工阅读和分享。导出读取已有保存结果，不重新提问、抽取事实或请求模型；覆盖、候选和时间线部分由已有数据在本地派生。未持久化的临时失败反馈不进入报告。

报告可能含案件名称、问题、回答、引用原文、Claim、矛盾与 Timeline，属于敏感文件。当前只有 JSON / Markdown，没有 PDF 报告导出。**分析导出 ≠ 完整备份**：它没有可恢复的完整数据库、原始 PDF 和索引，不能用来恢复全部工作数据。

<a id="guide22"></a>

## 22. 创建完整备份

1. 展开页面上方 **数据管理：完整备份 / 恢复**。
2. 点击 **创建完整备份**，等待验证完成。
3. 点击 **下载完整备份**，将 `.casefile-backup.zip` 保存到安全位置；完整名称为 `casefile-ai-{artifact_id}.casefile-backup.zip`，其中编号由系统生成。
4. 确认文件已下载，再按需要保存到另一存储位置。不能只把同一磁盘上的副本视为设备损坏后的保障。

这是整个应用的备份，不限当前案件：包括数据库、所有数据库引用的 PDF 历史版本及文件清单（manifest）。不包含 API key、`.env` / `config.env`、日志或模型缓存；但数据库与 PDF 本身包含卷宗内容，**排除配置不等于脱敏**。

**备份没有加密**，请限制访问，不随意发送。创建备份和恢复需要额外空间和等待，当前没有自动备份、自动清理旧备份或云同步。必要时通过预检确认备份可读，更新前尤其应备份。

<a id="guide23"></a>

## 23. 恢复备份到新副本

恢复不会直接覆盖当前数据，流程是 **上传 → 预检 → 明确确认 → 创建新目录副本 → 验证**。

1. 在 **数据管理：完整备份 / 恢复** 的 **选择完整备份包** 选择 `.casefile-backup.zip`。
2. 点击 **验证备份并预览恢复**，等待预检，核对案件、材料和历史版本数量。
3. 勾选“我理解：此操作仅创建新的恢复副本，不覆盖、不删除、不自动切换当前工作数据。”
4. 点击 **确认创建新副本**。只有看到 **恢复副本已验证完成** 后才可使用该副本。
5. 核对数量和保存位置。原工作数据仍保持原样，失败不会覆盖它；不要使用标记未完成的目录。

副本默认保存在 `%LOCALAPPDATA%\CaseFileAI\data-management\restored\` 下。恢复不是案件合并，也不会自动把副本显示为当前工作数据。这样设计让失败不会破坏原数据，并保留回退选择。

需要切换到副本时：先 Stop，保留原配置值；用记事本打开 `%LOCALAPPDATA%\CaseFileAI\config.env`，同时修改以下两项，**逐字使用恢复结果显示的实际路径，不要复制占位路径**：

```dotenv
CASEFILE_DATA_DIR=C:/Users/your-name/AppData/Local/CaseFileAI/data-management/restored/RESTORE_ID
CASEFILE_DATABASE_URL=sqlite:///C:/Users/your-name/AppData/Local/CaseFileAI/data-management/restored/RESTORE_ID/casefile-ai.db
```

保存后 Start，检查案件、历史材料和索引。需要回退时 Stop，恢复原两项（原来没有这些项则移除本次添加项），再 Start。恢复不提供 API key，仍沿用独立配置。

恢复结果会提示当前配置文件。Windows 产品入口实际应改 `config.env`，不要去修改程序目录 `.env`。如此前由维护人员指定了外置配置或环境变量，先确认实际生效配置；不要手工修改数据库。路径与进阶校验见 [数据管理说明](data-management.md)。

## 24. 查看系统状态

展开 **系统状态**，点击 **刷新系统状态**。面板显示：

| 项目 | 怎么看 |
| --- | --- |
| 数据库 | “可用，结构为当前版本”表示能读本地数据库且版本符合要求；异常时核对配置并按安装说明处理 |
| 数据目录 | “可写”表示当前存储目录可写；不可写时核实目录权限、空间与路径 |
| 本地向量模型（Embedding） | “可用 / 尚不可用”与“已加载 / 尚未加载”分别表示文件准备和本进程加载情况 |
| OCR | 依赖与模型文件是否可用；缺失时重新 Setup / Prepare |
| AI 问答 | 配置、启用和本次运行中是否曾成功连接是三件不同的事 |
| 安全日志 | 文件日志是否可写；异常时先核对日志目录 |

“已配置”（configured）是必要配置已填写；“可用”（available）是当前检查认为必要资源存在，不保证推理一定成功；“已加载”（loaded）是本进程已载入模型；“曾成功连接”（connection verified）表示本次运行有过成功调用，不保证此刻网络正常。刚启动“尚未加载”或“连接尚未验证”并不等于故障。

刷新只检查本地状态，不发送模型测试请求，也不会下载权重。缺少可选云配置本身不阻止本地功能。

面板下方折叠的 **技术详情** 显示具体数据目录、数据库、日志和配置文件路径；不会显示凭据。没有“测试模型连接”按钮。默认位置见下一章；若改过位置，以技术详情中的实际路径为准。浏览器能打开或服务就绪也不代表全部模型功能都已准备。

## 25. 配置 AI 模型服务

默认不启用外部模型。只有需要新问答、事实抽取或语义矛盾判断时才考虑配置，并先检查单位政策及服务的数据政策；真实敏感卷宗不得发送到公共模型 API。当前不是本地大语言模型交付，也没有 GUI 设置页面或自动脱敏。

1. Stop，使用记事本打开 `%LOCALAPPDATA%\CaseFileAI\config.env`。若找不到文件，先运行 Setup；在资源管理器地址栏输入 `%LOCALAPPDATA%\CaseFileAI` 可打开目录。
2. 从所用服务的正式配置说明取得兼容接口地址（endpoint）、模型名（model）和个人凭据（API key）。endpoint 是接口地址，不是聊天网页地址；本手册不提供真实凭据。
3. 将下面占位值换成有效值，同名项只保留一行，保存为 UTF-8 的 `config.env`，避免保存成 `config.env.txt`。

```dotenv
# 仅供合成或已人工脱敏材料；下面均为占位值，不能直接连接。
CASEFILE_LLM_ENABLED=true
CASEFILE_LLM_BASE_URL=https://MODEL_ENDPOINT.invalid/v1
CASEFILE_LLM_MODEL=YOUR_MODEL_NAME
CASEFILE_LLM_API_KEY=YOUR_API_KEY
```

4. Start，刷新系统状态，确认“已配置”“已启用”；用合成材料的具体问题验证，不要用真实敏感卷宗试连接。
5. 暂停外发时 Stop，改为 `CASEFILE_LLM_ENABLED=false`，再 Start。正在运行的服务不会自动读取配置修改。

**仅填写凭据 ≠ 自动启用**，还必须显式设置 `CASEFILE_LLM_ENABLED=true`。启用后相应操作可以发送必要内容，不承诺每次请求前再弹出确认。不要把 API key 放进材料、案件名称、问题、导出或截图。

若维护人员需要处理连接超时，可配置 `CASEFILE_LLM_TIMEOUT_SECONDS`（默认每次请求 60 秒），但不应以无限延长超时替代排查。模型需支持当前结构化输出；格式不兼容时请维护人员核对服务配置，不要要求程序接受未验证答案。

## 26. 数据保存在哪里

Windows 产品模式的默认位置如下，程序代码和用户数据分开：

| 内容 | 默认位置 |
| --- | --- |
| 用户配置 | `%LOCALAPPDATA%\CaseFileAI\config.env` |
| 案件数据根目录 | `%LOCALAPPDATA%\CaseFileAI\data` |
| 数据库 | `%LOCALAPPDATA%\CaseFileAI\data\casefile-ai.db` |
| PDF 历史原件 | `%LOCALAPPDATA%\CaseFileAI\data\originals` |
| 日志 | `%LOCALAPPDATA%\CaseFileAI\logs` |
| 运行记录 | `%LOCALAPPDATA%\CaseFileAI\runtime` |
| 备份、导出、恢复副本 | `%LOCALAPPDATA%\CaseFileAI\data-management` |

在资源管理器地址栏输入 `%LOCALAPPDATA%\CaseFileAI` 并回车即可打开。PDF 按内部编号保存，不要通过重命名或删除这些文件整理案件，也不要单独复制运行中的数据库来代替完整备份。

这些是默认值，不保证等于你当前配置。`CASEFILE_APP_HOME`、`CASEFILE_DATA_DIR`、`CASEFILE_DATABASE_URL`、`CASEFILE_LOG_DIR` 可由维护人员改到其他位置；使用恢复副本后数据位置也会改变。数据库可能在数据目录之外，切换时必须同时核对数据库和 PDF 路径。

程序不会自动迁移旧开发目录中的案件或 `.env` 凭据；需要迁移时先用原入口完整备份，再恢复。运行记录不是案件数据，崩溃后的过期记录由 Start 安全处理，不要自行根据 PID 结束未知进程。

<a id="guide27"></a>

## 27. 日志在哪里

默认 `%LOCALAPPDATA%\CaseFileAI\logs` 内：`app.log` 为应用安全事件，`error.log` 为应用错误事件，`launcher.log` 为 Setup / Prepare / Start / Stop 阶段结果。日志支持轮转，不是无限保留的操作历史。

Launcher 日志只记录时间、阶段、结果或错误类别、PID 和端口；应用日志记录白名单事件及必要诊断编号。这些安全日志不记录 API key、控制凭证、问题、检索词、证据原文、PDF、prompt、模型响应或原始异常。文件日志无法写入时可能回退安全输出，系统状态会提示。

报错时先记录时间、中文现象与 **技术详情** 中的诊断编号（若提供）。向维护人员提供必要安全日志即可；不要直接发送整个用户目录、配置文件或真实卷宗。日志不是备份，也不能用来恢复案件。

## 28. 常见错误：现象、含义和处理

技术详情中的代码用于排查，不要求记忆。表中的 401 / 403 / 429 / 503 是模型服务的返回状态，软件可能用安全类别呈现。

| 现象 / 类别 | 含义 | 用户应做什么 |
| --- | --- | --- |
| AI 问答尚未配置 / model_not_configured | 接口地址、模型名、API key 未完整填写 | 需要 AI 时按第 25 章配置；本地功能可继续用 |
| AI 问答调用未启用 / model_disabled | 已配置，但未允许模型外发 | 确认材料可外发后显式启用并重启；否则保持本地使用 |
| 凭据无效 / authentication_error / 401 | 服务拒绝凭据 | Stop 后核对 key、服务区域和 endpoint，更新配置再启动；勿公开 key |
| 没有权限 / permission_error / 403 | 账户无模型或服务权限 | 核对模型名和账户授权，请服务提供方或维护人员协助 |
| 请求受限 / rate_limited / 429 | 服务限流或额度不足 | 等待后再试，检查配额；不要连续重复点击 |
| 响应超时 / timeout | 单次模型请求等待超限 | 检查网络和服务状态，稍后重试；不要当成有效答案 |
| 服务暂不可用 / unavailable / 503 | 模型服务临时不可用 | 等待后重试，持续出现时记录诊断编号 |
| 无法连接 / connection_error | 网络、地址或服务无法访问 | 核对 endpoint、网络及单位代理策略，请维护人员排查 |
| 返回格式无效 / invalid_response | 模型输出不符合验证要求 | 本次没有有效结果；核对兼容配置或稍后重试，不手工改数据库“修复” |
| 索引未完成 / index_incomplete | 当前材料尚未完整索引 | 到材料与索引建立 / 更新索引，再重新提问 |
| 索引需要更新 | 新材料、版本变更或索引版本变化 | 更新索引；不会重新 OCR |
| 上次索引失败 / index_failed | 本地处理未完成 | 原材料保留；检查模型、空间和权限后重试 |
| OCR / 解析失败 | 本地依赖、模型或 PDF 页面无法处理 | 重新 Setup / Prepare，核对源 PDF；重要文字人工复核 |
| PDF 导入失败或“输入或文件无法处理” | 文件损坏、加密、非 PDF 或超限；界面可能只给通用提示 | 在阅读器检查文件，确认不超过 50 MiB、1–500 页、未加密，必要时重新生成 PDF |
| 再次导入但没有新材料 / 重复 PDF | 相同内容复用了已存在材料 / 版本 | 核对已有材料与版本；需要修订时选择真正不同的文件并添加新版本 |
| 端口 8000 已被其他程序占用 | 不是已验证的可复用实例 | 核实程序并正常停止，不强杀其他 Python、不期待自动换端口 |
| Start 没打开浏览器 | 浏览器打开失败，或服务尚未成功启动 | 若提示就绪则手动访问显示的地址；若启动失败则查日志及原因 |
| Prepare Models 失败 | 本地模型准备不完整 | 检查网络、缓存、原生运行库、空间与权限，再重跑；已有案件不受影响 |
| 备份损坏 / invalid_backup / invalid_manifest / checksum_mismatch | 文件清单、内容或完整性无法通过预检 | 使用完整的另一份备份或重新下载；不要手工解包覆盖当前数据 |
| 恢复校验失败 / database_integrity / database_references / restore_failed | 新副本完整性或来源链不合要求，或空间 / 权限不足 | 保留原数据，记录诊断编号，检查空间并换有效备份；不要启用未完成副本 |
| 未来版本备份 / future_backup / future_schema | 备份版本高于当前程序或结构未知 | 使用相应版本恢复，不绕过版本校验 |
| 缺少 PDF / missing_pdf / pdf_checksum | 原文件缺失或与记录不一致 | 停止整理文件；请维护人员核对已验证备份，不生成残缺备份 |
| 无法连接本地服务 / local_connection_error | 服务已停止或启动失败 | 使用 Start，确认就绪，再刷新页面 |

不建议通过修改数据库、删除 originals 或屏蔽验证来排错。无法判断时，按 [最后的检查清单](#guide33) 收集安全信息。

## 29. 隐私与云模型边界

“本地优先”意味着材料保存和许多处理在电脑上完成，**不意味着所有操作都没有外发**。默认不启用云模型；开启后，对应操作可能调用配置的服务。

| 在本机完成的部分 | 可能发送到配置模型服务的部分 |
| --- | --- |
| 原始 PDF 保存、文本解析与 OCR | 基于证据问答（QA）及可能的重试 |
| 本地数据库、文字分段、关键词与 BGE 向量计算、本地检索 | 回答事实的支持检查、问题 / 来源对齐验证 |
| Coverage 来源 / 文本覆盖检查、候选生成 | Claim 抽取及其事实支持 / 质量检查 |
| 日期 / 金额矛盾的规则比较 | 行为 / 人物的语义矛盾判断 |
| Timeline 整理、已有结果读取、备份 / 恢复 / 导出 | 上述操作所需的问题、事实、证据片段及必要来源信息 |

这些外部调用不上传整个 PDF 文件作为附件，但会发送被选中的证据文字；文字、文件名、问题和来源标识本身也可能含个人或商业信息。“只发片段”不等于没有敏感数据，部分验证也会重复发送相关内容。

**系统不会自动脱敏。真实敏感卷宗不得发送到公共模型 API。** 涉及敏感材料前必须确认单位政策和所用服务的数据、留存政策；公共 API 的开发、演示与试用只使用合成或人工脱敏材料。不要因“已启用”就认为符合保密要求。

首次安装 / Prepare 可能连接依赖或模型下载站点，这是取得软件 / 权重，不是对卷宗做 AI 分析。无云配置时本地功能仍可用，但缺少权重时仍可能联网下载，不能据此承诺完全离线。备份和分析导出不自动上传；用户自己分享文件会产生另一条外发路径。

本地文件、备份和报告没有内置加密。控制本机账户、磁盘和共享目录访问；不要把 `config.env`、整个用户目录或含原文报告公开。当前不是多用户企业平台，没有用户账号和企业权限管理；本地服务默认只监听本机，不应自行开放到局域网。

<a id="guide30"></a>

## 30. 已知限制

1. OCR 易混字符无法保证安全自动纠正，重要字段需核对原文。
2. 极短 / 歧义查询可能无法唯一命中；没结果不等于事实不存在。
3. 系统优先安全拒答，也可能出现本来可答却拒答（false abstain）。
4. Citation 合法不等于法律结论正确，补充引用也可能需要人工核对。
5. 语义矛盾可能“待确认”；候选可能漏召回，不能保证发现所有矛盾。
6. Coverage 只针对当前已有已验证回答，不代表完整案件覆盖。
7. 云模型可能超时、限流（429）、暂不可用（503），并产生服务费用。
8. 备份未加密，没有自动备份保留、云同步或增量备份；导出不能代替备份。
9. 当前不是完全本地大语言模型，不自动脱敏。
10. 当前不支持 GUI 永久删除案件 / 文档，不支持恢复原地覆盖或自动切换。
11. 当前不是多用户企业平台，没有用户账号、企业权限或内置加密。
12. 只支持 PDF；导入、索引和分析为同步操作，没有后台队列、取消或断点续作。大文件会等待并占用额外磁盘。
13. 时间线不推断未知日期、不自动合并重复事件，也不是完整事实清单。
14. 版本信息和具体路径通过来源接口和系统状态取得；连接失败时先刷新并检查服务，不根据文件名猜测版本。
15. 正式 MCP 入口尚未接通，属于开发 / 未来功能，不属于当前 Windows MVP。
16. Windows 验证是在当前电脑上隔离用户目录与新环境完成；另一台物理机器、空缓存完整下载和企业策略仍待最终验收复核。

<a id="guide31"></a>

## 31. 更新程序

1. 创建完整备份并下载保存，记录当前配置与实际数据位置。
2. Stop，等待服务停止。
3. 将新程序完整解压到可写程序目录，保留同一个用户目录；不要把旧环境文件夹直接搬到新位置。
4. 双击 Setup；需要时重新 Prepare Models。
5. Start，检查案件、原文、历史版本和索引状态；索引需要更新时处理。

用户数据默认位于 LocalAppData，更新程序不会自动删除它，也不会覆盖已有 `config.env`。当前没有网络自动更新器。新版本可能升级数据库，回退应使用已验证备份和兼容程序，不能直接拿旧程序打开新结构；详见 [安装说明](windows-installation.md)。

<a id="guide32"></a>

## 32. 卸载程序与删除用户数据

**只卸载程序**：先 Stop，备份并核实目录，再在资源管理器删除程序目录及其桌面快捷方式。默认 `%LOCALAPPDATA%\CaseFileAI\data` 会保留，不会因为删除程序而自动删除案件。若程序目录还放着旧开发数据、手工备份或 `.env`，先保存它们，不能盲目整目录删除。共享 Python、uv 和模型缓存不要因卸载本应用随意删除。

**确实要删除全部用户数据**：这是额外手工操作，先确认保留要求、备份和实际位置，Stop 后在资源管理器核实对应用户目录，再自行删除。自定义外置数据库、恢复副本、下载到其他位置的备份 / 报告需分别核对；只删除默认 data 目录并不等于清除了这些文件。删除不可由软件撤销，也不保证磁盘安全擦除。当前 GUI 没有永久删除按钮或自动清空脚本。

<a id="guide33"></a>

## 33. 遇到问题先检查

1. Start 是否显示成功？是否使用当前入口显示的本机地址？
2. 当前案件选对了吗？刷新 **系统状态**，先处理本地依赖、目录和数据库异常。
3. PDF 是否已导入？能否打开该版本原文，页数是否符合预期？
4. **材料与索引** 是否“索引可用”？导入和索引不要混为一步。
5. 扫描件识别是否正确？搜索是否过短或事件范围不明确？
6. 若操作需要 AI，配置是否完整、是否显式启用、保存后是否 Stop / Start？
7. 网络 / 服务是否正常？“连接尚未验证”只是尚无成功调用；用合成材料检查，不用敏感卷宗试连。
8. 当前证据能否支持问题？证据不足时补材料或缩小问题，不强求模型输出。
9. 记录操作时间、现象、错误类别和诊断编号，查看安全日志位置；不发送 key 或卷宗来排错。
10. 必要时正常 Stop 后再 Start；仍失败则向维护人员提供上述安全信息。不要优先重装、删除 data 或修改数据库。
