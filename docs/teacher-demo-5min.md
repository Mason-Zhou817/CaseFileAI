# CaseFile AI 教师演示：4 分 50 秒脚本

录制前使用全合成案件预先导入 PDF、建立索引，并准备一条已验证金额 Answer、一条日期 Claim、反馈摘要及离线回归报告。确认 GUI、CLI、MCP 指向同一演示数据目录，Qwen 已明确启用且额度可用。先在本机排练并计时；模型请求耗时不可预测，可预先展示已保存回答，同时如实说明该画面不是现场新请求。屏幕避免出现 API key、配置文件、真实案件与本地个人路径。下列时间为操作与旁白的上限，实际视频须本人录制检查。

| 时间 | 屏幕操作提示 | 中文旁白稿 |
| --- | --- | --- |
| 0:00–0:30 | 标题、公开 GitHub 页面、全合成案件概览。 | “这是我完成的 CaseFile AI，一个本地优先、证据可追溯的卷宗分析系统。它把 PDF 材料、检索证据、回答与后续事实分析连接起来。今天展示的是合成案件，不包含真实客户材料。” |
| 0:30–1:20 | GUI：材料与索引 → 文档页 → Search → 提问与引用；放大金额答案来源。 | “材料导入后保留文件版本和页码，本地建立关键词与向量索引。搜索显示原文片段。问答以本轮检索证据为范围，回答卡片展示验证状态和 Citation；我可以打开原文件、版本、页码核对，而不只看一段模型文字。证据不足时系统会拒答。” |
| 1:20–2:10 | 事实与覆盖检查 → 候选与矛盾 → 时间线；点开双侧来源。 | “已验证回答可以抽取 Claim。每条 Claim 保留来源，检查主体、金额或日期等字段。矛盾分析会显示两端证据；如果无法确认同一事件，它标为待确认，不强行下结论。时间线按有日期的事实排列，仍可回到原始材料。” |
| 2:10–2:50 | 展示无证据题拒答、System Status、不同案件；可短暂展示版本 1.1.0。 | “可靠性方面，系统检查 Citation 是否属于本轮证据和当前案件，并核对所问字段与来源。系统状态列出数据库、索引、模型配置和本地依赖；错误按类别显示，日志避免记录原文和密钥。它是单机辅助工具，校验通过不等于法律结论一定正确。” |
| 2:50–3:30 | 终端预置 `$caseId`：`casefile-ai case list`、`search --case $caseId "付款"`、`ask --case $caseId "付款金额是多少？"`、`timeline --case $caseId`。 | “同一套服务也提供正式 CLI。这里依次列案件、检索、问答和查看时间线。CLI 可用人类可读输出，也可加 `--json` 供脚本调用；没有配置模型时，新问答会明确返回模型未配置。” |
| 3:30–4:10 | Codex CLI 连接正式 `casefile-ai-mcp`；让 Agent 调用 `list_cases`、`search_evidence`、`ask_case`，展示工具名和结构化结果。 | “本地智能体还可以通过标准 MCP stdio 入口使用 CaseFile AI。这里是正式服务进程，不是测试替身。工具结果带案件与来源；PDF 导入默认关闭，只有配置允许目录才开放。MCP 客户端怎样转发结果仍需单独评估隐私。” |
| 4:10–4:40 | GUI 点“错误 / citation”反馈 → Summary；切到已准备的 approved eval 与回归报告。 | “用户可以对真实回答提交正确、部分正确、错误或证据不足反馈，并选失败类别。反馈先进入 pending，由人审核并填写预期答案与证据，再导出评测 staging，离线跑回归。它不会自动训练，也不会自动改 Prompt。” |
| 4:40–5:00 | GitHub 地址和三入口摘要；最后一页写已知限制。 | “项目源码在屏幕上的 GitHub 地址。GUI、CLI、MCP 共享案件服务，反馈支持下一版本改进。当前限制包括 Qwen 是可选云调用、OCR 和语义判断可能出错、备份未加密；真实材料仍需人工核对。” |
